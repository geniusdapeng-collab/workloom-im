# 灰度观察

## 一、何时调用
- 新行业包/新版本发布时；上架审核（五项检查单）时；滞后客户跟踪时。

## 二、执行步骤
1. **上架审核**：五项检查单——脱敏检查（不得含种子客户数据）/考题通过率/围栏绑定完整性/schema 兼容（只许新增字段与枚举值）/回滚可用性；双人审，任一否决不上架；
2. **批次发布**：内部租户 → 5% → 50% → 100%，每批启动走 R-PL5 人审；
3. **观察期监控**：每批次 24h 自动采集错误率/工单密度/围栏拦截异常/积分消耗异常；超阈值 → 自动暂停并回滚上一批次（台账+快照一键恢复）；
4. **版本矩阵**：客户×行业包×版本三维登记；滞后客户自动标红并生成升级建议；
5. **升级后跟踪**：客户收到升级说明（新增能力/变化点/回滚方式）；升级后 7 天跟踪工单密度。

## 三、边界与围栏
- 每批灰度 R-PL5 人审；回滚本身也走审批（防误回滚）；
- 一切激活留痕：谁发布、谁审批、哪个批次、观察期数据——版本矩阵可回答"3 个月前那次故障时这个租户跑的是哪个版本"。

## 四、与其他技能的协作
- 上游：ai-pm V3 交付（行业通用能力）；下游：kb-fresh（版本对齐）、health-scan（版本滞后维度）。
