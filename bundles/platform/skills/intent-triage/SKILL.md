# 意图分诊

## 一、何时调用
- 技术支持通道每一轮客户消息到达时；
- 同会话检测到新议题需要拆单时。

## 二、输入契约
- 客户消息原文 + 会话历史 + 客户档案快照（租户 ID/角色/行业包及版本/实例版本，脱敏）。

## 三、执行步骤
1. **规则先行**：关键词/正则快速命中（如"积分""扣费"→billing；"报错""不工作"→bug_report）；
2. **LLM 兜底**：规则未命中走模型分类（复用底座 service-dialog）；
3. **置信度判定**：低于阈值必须追问确认（"您是想反馈故障，还是提个新功能建议？"），禁止猜路由；
4. **情绪检测**：负面情绪自动升一级优先级；强烈不满 → complaint 高优直通值班人；
5. **路由落账**：路由决策（意图/置信度/依据）以工单为锚点落事件库——可审计"为什么这么分"。

## 四、路由表与目标自动化率
| 意图 | 路由 | 目标自动化率 |
|---|---|---|
| kb_qa 使用咨询 | 知识库直接作答 | ≥85% |
| feature_request 功能需求 | requirement-clarify 澄清流程 | 澄清 100% AI |
| bug_report 故障报告 | 故障工单 → 运维组 | ≥70% |
| billing 计费账单 | 自动查账作答，争议转人工 | ≥80% |
| complaint 投诉 | 高优 + 值班人即时介入 | 人工为主 |
| chat 闲聊 | 礼貌应答，不建单 | 100% |

## 五、边界与围栏
- 权限面：tickets.read/route；批量动作 R-PL2。
- 同会话多轮归并为一单；新议题提示"这个问题我给您单独建一张工单跟踪"后自动拆单。

## 六、与其他技能的协作
- 下游：ticket-ledger（建单记账）、requirement-clarify（需求澄清）、credit-reconcile（查账作答）；
- 误分率高的意图 → intent_route_tuning 策略提案（strategy-forge）。
