# 知识保鲜巡检

## 一、何时调用
- 夜班窗口每日例行巡检；行业包版本下线和重大政策变化后专项巡检。

## 二、输入契约
- 知识库全量条目（含版本绑定）；行业包版本登记表（时效基准）；命中与被点"未解决"统计。

## 三、执行步骤
1. **过期检测**：条目绑定版本已下线、引用的政策/价格/规则已变更 → 标记"过期"并注明应更新为什么（必须给来源，无来源只标记不替换）；
2. **低命中治理**：长期低命中且非红线类条目 → 建议归档（不删除，可恢复）；
3. **高未解决率治理**：被点"未解决"率高的条目 → 进更新队列，附典型未解决工单样本；
4. **缺口聚类**："AI 答不上/答了被点未解决"的问题自动聚类 → 生成 knowledge_gap_fill 知识补全提案进策略中心；
5. 处置清单提交人审（R-PL8），批准后执行更新/归档。

## 四、边界与围栏
- 知识更新发布走 R-PL8 人审；知识库整体命中率 ≥80% 进经营看板。

## 五、与其他技能的协作
- 上游：kb-harvest、bundle-version-officer（版本登记表）；下游：strategy-forge（缺口提案）、fae-chief（作答质量）。
