# 工单记账

## 一、何时调用
- 每次会话建单/拆单/归并时；每次状态流转、处理动作、对客户发言时。

## 二、输入契约
- 工单结构化字段：意图、类型、优先级、客户档案快照、证据（对话/截图/日志句柄）、SLA 计时器、路由轨迹、关联需求/交付/知识条目。

## 三、状态机
```
新建 → 已分诊 → 处理中 ⇄ 待客户（等客户补充/确认）→ 已解决 → 已关单
  任意状态 → 已升级（人工介入）↺ 回到处理中
  已关单 → 第3天自动回访 →（不满意可重开，关联原单）
```

## 四、执行步骤
1. **建单**：同会话多轮归并；幂等建单（重复事件不重开）；
2. **记账**：每个状态变更、每个处理动作、每句对客户的话，以工单为锚点落事件库——账本只增不改，纠错走补偿事件；
3. **SLA**：故障类首响 ≤5min；需求类 24h 内完成澄清；咨询类即时；超时自动升级值班人；
4. **透明**：客户随时可查状态与预计时间；状态变更自动推送（立项/开发/评测/发布）；
5. **边界**：待客户 72h 未回复自动提醒一次；7 天未回复自动关单（标注"客户未确认"），回访仍执行。

## 五、边界与围栏
- 人工介入队列（"需介入"）携带完整上下文摘要，人类零信息差接管；
- 随机抽已关单工单必须能完整重放事件时间线（谁、何时、做了什么、说了什么）——验收红线。

## 六、与其他技能的协作
- 上游：intent-triage；下游：requirement-clarify（需求类）、incident-playbook（故障类）、kb-harvest（关单沉淀）。
