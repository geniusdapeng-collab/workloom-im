# 模型能力侦察

## 一、何时调用
- 夜班窗口监控模型厂商发布渠道；
- 捕获新模型/新版本发布时自动触发试跑。

## 二、输入契约
- 模型版本登记表（model 对象）；本产品 eval 子集（与产品真实场景强相关）；当前流量结构（成本测算基准）。

## 三、执行步骤
1. 监控厂商发布渠道（官网/博客/API 变更日志），捕获新模型信号；
2. **换型触发器判断**（三者其一才继续）：①上下文长度让现有架构变可选；②价格让此前否决的用例成立；③预告能力对本产品场景有意义性跃升——纯 benchmark 新闻直接归档为营销噪声；
3. 触发器成立 → 用本产品 eval 子集对新模型试跑（谷时窗口控成本）；
4. 产出三轴阶跃报告：质量（实测通过率，标注样本量与置信度）/ 时延 / 成本（按真实流量结构测算月成本），附换型建议、风险评估与回滚预案；
5. 报告提交人审（R-PM9 模型路由切换必审）；同步知识保鲜官更新模型代际信息。

## 四、边界与围栏
- 权限面：联网只读；报告写库；试跑走凭据 L4 注入、谷时窗口。
- 绝不转述厂商宣称数据作为结论（仅作 C 级线索）；无实测不产出换型建议。

## 五、与其他技能的协作
- 上游：industry-radar（信号源）；eval-forge（试跑用 eval 子集）；
- 下游：kb-fresh（模型代际信息入库保鲜）；model-router（人审通过后的路由切换执行）。
