# 微调全生命周期跟踪

## 一、何时调用
- 团队提出"要不要微调一个模型"时（强制前置评估）；
- 微调任务经人工白名单批准后，全周期跟踪。

## 二、输入契约
- 候选任务定义与目标场景；现有数据集规模与质量；关联 eval 集（训后对比基准）。

## 三、执行步骤
1. **微调四问前置评估**：①现有数据量与质量是否够？②任务模式是否稳定（不稳定则微调追不上变化）？③错误成本是否高到值得？④延迟/成本约束下是否比 RAG/prompt 工程划算？任一不满足 → 建议不走微调并说明理由；
2. 四问通过 → 数据集版本登记（dataset 对象：规模/来源/脱敏状态）；
3. 微调任务发起走 R-PM11（block 级，仅人工白名单放行）；
4. 训练状态跟踪：轮次、损失曲线、中间检查点留痕；
5. 训后自动 eval 对比基线（同一 eval 集：基座模型 vs 微调模型）；
6. 产出上线裁决包（对比报告+成本测算+回滚预案）进审批流。

## 四、边界与围栏
- 权限面：finetune_run/dataset 写操作一律 R-PM11 block，仅人工白名单放行；数据外发一律 block。
- 训练成本逐事件计量；数据集脱敏是登记前置硬条件。

## 五、与其他技能的协作
- 上游：eval-forge（训后对比基准）；model-scout（基座选型参考）；
- 下游：prompt-regression（微调模型上线后的 prompt 兼容性回归）；release-cut（上线台账）。
