**两处可简化（本次仅出建议，未动导航结构）**

1. `资料录入` 与 `定制中心`：前者只产出"意图卡"，后者负责考试→灰度→全量→回滚；两步合成一个入口 + 两个页签，
   对普通用户更直观。合并需要一次路由与页面结构改动，建议单独任务卡。
2. `伙伴授权`：使用频率低、对象是外部伙伴，适合作为 `成员管理` 的第三个分区，减少一级入口。

**不做的**：不删除任何入口。22 项里没有任何一项是"重复实现另一项"；它们分别承担扫描（统一待办）、
深做（任务/审批）、审计（账本/规则/考试）三件不同的事。菜单偏长的真正原因是**分组默认展开**，
解决办法是分组折叠与置顶常用项（后者已是既有能力），不是删入口。

## 三、引导话术走查（本次已改 / 建议后置）

**已改：**

- 装配检查单：`forbidden / Schema / preset / yml / 单调守卫 / 五要素之⑥皮肤` 等工程词全部替换为业务词；
  修复建议从"回 P3 补 forbidden"改为"到「经营报告 · 客户档案」补齐硬约束"。
- 审批清单：补"请于 X 前处理 · 超时保持未批准，不会自动放行"，去掉"系统会自己处理"的误解空间。
- 数字员工列表：一句话状态从"已关联 N 条围栏 / 校验失败"改为"待命 / 夜班在线 / 只读岗位 + N 个技能包"，
  等级段位与战绩移入员工档案详情，窄列不再换行成三四行；员工档案详情顶部补一句岗位职责。
- 提醒与错误文案中的"围栏/记忆/考试院"统一改为新术语（含 HUD 提示、通知、空态）。

**建议后置（需行业包内容改写，属各行业文案批次）：**

- 行业包内的岗位说明仍带工程记号（例如 `L3.3`、`robots`、`API`、`FAQ` 混排），显示时会回落成兜底文案。
  统一口径：**面向用户的岗位说明只用中文业务词；确属行业通用缩写（如 OCC/PMS/WiFi）走 `ui.safeTerms` 声明**。
- 技能说明同理：技能正文属于行业资产，建议在各自仓库按"一句话价值 + 触发条件 + 边界"重写。
