# 仙女座运营运维系统 · 使用手册（运营人员培训版 V1.0）

> **读者**：平台运营/运维人员（1–2 人编制）。
> **目标**：读完本手册并通过上岗考核后，你能够独立运营这套系统，服务千万量级 B 端客户。
> **一句话总纲**：这套系统的执行者是 17 名数字员工，不是你。你只做两件事——**裁决**（审批高风险动作）与**经营**（定方向、看大盘）。你的工作效率不取决于手速，而取决于**审批判断力**和**对系统的信任校准**。

# 第一部分 认知篇：先搞懂你管的是什么

## 1.1 系统是什么

仙女座是 WorkLoom 平台方服务所有企业客户的**服务中枢**。客户在自己的客户端里像发消息一样获得技术支持；每一条诉求沉淀为一张"给 AI 看的工单"，在系统中自动流转、记账、闭环；平台知识库为每次服务提供弹药；系统从服务数据中持续洞察、自动产出运营策略，**经你审批后自动上线**。

四根支柱：

| 支柱 | 干什么 | 负责的数字员工班组 |
|---|---|---|
| **桥梁** | 客户与平台之间对话式服务通道 | FAE 工单组（平台客服长/工单分诊官/需求转运官） |
| **账本** | 工单结构化流转、记账、可追溯 | FAE 工单组 + 平台运维组 |
| **弹药** | 平台企业知识库，让 AI 有知识地说话 | 知识管理组（知识馆长/知识保鲜官） |
| **引擎** | 自生长：洞察→策略→灰度→归因 | 策略运营组（洞察分析师/策略工程师/效果评估官） |

支撑班组：客户成功组（健康官/续费预警/onboarding 向导）、计费账务组（对账官/账单官）、平台运维组（巡检官/故障应急官）、行业包运营组（包版本官/上架审核官）。

## 1.2 为什么一两个人就够

传统客服中心服务千万客户需要数千人，因为**执行**靠人。仙女座的执行全部归数字员工：

| 工作量 | 谁干 |
|---|---|
| 每天数万次客户对话、工单分诊、知识作答、SLA 监控 | AI（平台客服长/分诊官） |
| 需求澄清、确认单、研发注入、进度回传、交付回访 | AI（需求转运官）+ ai-pm 研发团队（也是 AI） |
| 每日对账、健康分计算、知识保鲜、灰度观察、洞察报告 | AI（夜班班组，02:00–07:00 自动跑） |
| **每天几十到几百个审批决策** | **你**（这是你的主战场） |
| **每周几次方向性判断**（策略走向、规则调整、复盘定调） | **你** |
| **偶发 P0/P1 故障的止血与宣告** | **你**（大部分止血动作系统已自动完成） |

**关键认知：你的工作不是"处理工单"，而是"管理一个处理工单的系统"。** 你的产出以三个指标衡量：
1. **审批质量**——你放行的变更/策略/退款，事后证明是对的比例（目标 ≥95%）；
2. **响应及时性**——P0/P1 的宣告与止血时间（P0 ≤5min）；
3. **自动化率走势**——无需人工介入自动闭环的工单比例（目标 ≥85%，且逐月上升）。

## 1.3 系统的信任结构（你必须理解的底层逻辑）

```
客户 ──对话──> AI 客服 ──拿不准/高风险──> 审批队列 ──> 你（裁决）
                    │
                    └── 一切动作写入"事件账本"（只增不改、哈希链防篡改）
```

- **围栏（Fence）**：每个数字员工的写入级动作都被规则约束——`auto`（自动放行）/`review`（挂起等你批）/`block`（系统级禁止，你也无权放行，如客户数据导出）。规则清单在 **/p5 规则与权限**。
- **账本**：任何工单、任何审批、任何扣费都可完整回放"谁、何时、做了什么、说了什么"。你抽查任何一张单子，系统都能给你完整时间线。**这是你敢于让 AI 自动跑的根基。**
- **考试院**：数字员工上岗前要通过考试（含红线题：退款不审批、导出客户数据、跳过研发审批、绕过触达频控——答错一道即不合格）。你在 **/p24 考试院** 可以看到每个员工的成绩单。

# 第二部分 岗位篇：一两个人怎么排兵布阵

## 2.1 两种编制方案

### 方案 A：双人编制（推荐）

| 角色 | 职责 | 备份 |
|---|---|---|
| **运营 Owner（主）** | 审批裁决（C2/C3 变更、策略、退款）、经营方向、复盘定调、对外沟通 | 互为 AB 角 |
| **值班工程师（辅）** | P0/P1 故障响应、技术诊断、AI 开发 PR 评审、灰度发布管理 | |

两人互为 AB 角：任何一人的审批权限覆盖另一人（但**双人复核项必须真是两个人**——围栏放宽、保护清单变更、主备人工切换，系统强制两个不同账号）。

### 方案 B：单人编制（极限模式）

一人兼任，系统侧配合：
- 双人复核项改为「Owner + 系统延时复核」（提交后 24h 冷静期内可撤销，相当于把第二人换成时间）；
- 夜间 P1 降级为「系统自动处置 + 晨报裁决」，只有 P0 打电话；
- **单人连续值班不得超过 2 周**——系统会在第 14 天提醒你安排轮休（这不是福利建议，是防误判的工程措施：疲劳是审批质量的第一杀手）。

## 2.2 值班制度

| 时段 | 状态 | 你要做什么 |
|---|---|---|
| 工作日 09:30–19:00 | 在线 | 正常节奏（见第三部分） |
| 夜间 19:00–09:30 | 待机 | 数字员工+夜班班组全守；P1 自动处置进晨报；**只有 P0 会打电话给你** |
| 周末/节假日 | 待机 | 同夜间。周六上午花 30 分钟看周报 |

**P0 才会在夜间找你**——系统对 P0 的定义极其克制（数据安全/账本断链/全平台不可用/需主备切换），月均预期 ≤2 次。如果你连续一周夜里被叫，那不是事故多，是告警分级出了问题——提策略工单让策略工程师调整分级阈值。

## 2.3 账号与权限

| 账号 | 权限 | 纪律 |
|---|---|---|
| 个人主账号 | 审批（按角色矩阵）、全部只读页面 | 本人专用，开启 2FA |
| 紧急处置账号（break-glass） | 冻结/回滚/切换 | 双人分管两段口令，启用即 P0 事件留痕 |
| ~~共享账号~~ | 不存在 | 一切操作落账本到个人，共享账号等于放弃审计 |

# 第三部分 节奏篇：你的一天、一周、一月

## 3.1 你的一天（标准节奏，日均 3–4 小时）

| 时间 | 动作 | 页面 | 耗时 |
|---|---|---|---|
| 09:30 | **看清晨决策包**——三栏：昨夜已完成 / 待你审批 / 需你介入。先扫第三栏（通常 0–3 项），再批第二栏 | /p1 工作台总览 | 30min |
| 10:00 | **集中审批**（审批卡 3 分钟裁决法，见 4.2） | /p4 审批中心 | 60–90min |
| 11:30 | 抽查 3–5 张已关单工单（事件时间线回放）+ 看一眼服务大盘 | /p22 服务前台 | 20min |
| 14:00 | 经营面：健康分预警名单、策略效果榜、知识命中率 | /p21 董事长视图 | 30min |
| 16:00 | 按需：灰度批次审批 / AI 开发 PR 评审 / 复盘会 | /p25 开发场域等 | 弹性 |
| 19:00 | 收工前扫一眼「今日熔断/冻结记录」——系统替你挡了什么 | /p1 | 5min |

**原则：审批集中批，不随到随批。** 系统会给每个审批标 SLA（普通 4h、加急 30min、P0 即时），你按批次处理。随到随批看似负责，实则让你全天处于上下文切换中，判断力下降——审批质量比审批速度重要。

## 3.2 你的一周

| 日 | 主题 |
|---|---|
| 周一 | 上周策略效果榜过堂：哪些策略该固化、该回滚、该迭代（效果评估官已给出建议，你做取舍） |

| 周六 | （30min）周报扫读：大盘趋势、容量水位、SLO 消耗 |

## 3.3 你的一月

- **月度对账确认**（1 号）：对账官已完成全月三方对账，你确认零差异报告；有差异则资金冻结已自动生效，你主持核查；

- **季度**：故障演练（你必须亲自参与一次红蓝对抗）、主备切换演练、团队扩容评估。

# 第四部分 操作篇：工作台逐页手册

## 4.1 /p1 工作台总览——你的首页

**看什么**：清晨决策包三栏（昨夜已完成 / 待审批 / 需介入）、今日熔断冻结记录、SLO 仪表、告警流。
**判断标准**：
- 「需介入」>5 项 → 今天优先清这个队列，并思考：为什么是这些单？（同类多=知识缺口或产品缺陷，提策略）；
- 「熔断/冻结」出现非预期条目 → 立即点进去看触发依据（每条都带指标证据链）。

## 4.2 /p4 审批中心——你的主战场（重点掌握）

### 审批卡三段式结构

每张审批卡 = **动作描述**（要做什么）+ **证据链**（为什么建议做）+ **AI 建议**（建议批/建议拒+理由）。

### 三分钟裁决法

1. **30 秒看动作本身是否合法**：触及红线（R-PL4 数据导出、R-PL10 频控）的，AI 根本不会提交——如果你看到了，说明围栏失效，这本身就是 P1，先冻结再查；
2. **90 秒看证据链**：每个论据必须可下钻（点得开原始工单/原始数据）。**证据链残缺的一律打回**——你批的是证据不是结论；
3. **60 秒看 AI 建议的反方**：系统会同时给出「如果驳回，理由是什么」。两边都看完再落槌。

### 分类型审批要点

| 审批类型 | 触发围栏 | 你的判断清单 |
|---|---|---|
| 退款/赠积分 | R-PL1 | ①对账是否零差异（有差异先查账不赔钱）②金额 vs 该客户 ARR ③本周该客户第几次（≥3 次要查根因而非继续赔） |
| 批量客户操作 | R-PL2 | ①圈选条件是否精确（点预览看命中名单）②有无回滚/撤回方案 |
| 需求注入研发 | R-PL3 | ①确认单客户已显式确认（看确认记录原文）②热度=客户数×健康分×ARR ③与现有需求池是否重复（合并优先） |
| 灰度批次推进 | R-PL5 | ①上一批观察期数据：错误率/工单密度/围栏异常/积分异常四项全绿 ②回滚快照已就位 |
| 对外故障通报 | R-PL7 | ①事实部分是否与遥测一致（时间/影响面不夸大不缩小）②补偿方案是否已审批 |
| 知识发布 | R-PL8 | ①口径与定价/SLA 条款一致 ②绑定版本范围正确（别拿新版答案答旧版客户） |
| 策略激活 | R-PL9 | ①九要素齐备（无度量指标的策略不许批——这是铁律）②墓地查重（同类失败过的策略换马甲再来，拒）③熔断条件合理 |
| 触达频控例外 | R-PL10 | 默认不批。7 天 2 次是客户体验红线，例外必须书面理由 |

### 批量审批与默认动作库

系统会把**同类高置信审批**聚合成批（如"本周 23 张知识发布卡，AI 建议全批，证据链抽检 3 张全绿"）。你可以：抽验 20% → 整批通过。**抽验发现 1 张有问题 → 整批打回**，并触发该类的置信度降级（下周同类不再聚合）。信任是挣来的，也是动态校准的。

## 4.3 /p22 服务前台——服务质量抽查口

**看**：实时工单流、需介入队列、客户对话（只读）。
**标准动作**：
- 每天抽 3–5 张已关单工单，点「时间线回放」：分诊对不对？作答有没有知识出处？升级及不及时？回访完没完成？
- 发现 AI 答错 → 一键纠错（这条错误会自动回流：知识库修正候选 + 考题增补候选 + 该员工成绩记录）。
**判断标准**：抽查不合格率 >5% → 当天提单给知识馆长+策略工程师，查是知识问题还是分诊问题。

## 4.4 /p21 董事长视图——经营大盘

五块看板：服务大盘（工单量/首响/闭环率）、客户健康（分层分布+异动）、资金大盘（积分消耗/对账状态）、研发衔接（需求池/在途/交付）、系统健康（SLO/容量水位）。
**每周一必看**：策略效果榜——在线策略按归因效果排序，底部是「建议回滚」名单。

## 4.5 /p8 团队成员——数字员工编制管理

17 名员工的实时状态：任务量、成功率、围栏拦截率、审批通过率、考试成绩。
**你会用到的动作**：
- **暂停某员工**（它连续出错时）——点击暂停即生效，其任务自动转交备份岗位；
- **看员工成绩单**（/p24 考试院联动）：连续两周成绩下滑 → 触发重考或技能回滚。

## 4.6 /p9 夜班中心——夜间班组监督

夜班任务表（22:00–07:00）：巡检、对账、健康分、洞察、策略归因、回访调度、决策包生成。
**早上你要确认**：全部任务「已完成/有产出」。**漏触发 = P1**（监督器自动对账 cron 应触发表，漏了会报警——夜班、巡检、对账永不静默丢失）。

## 4.7 /p5 规则与权限——围栏查看（慎改）

你能看到全部 R-PL 规则及命中统计。**修改围栏是 C3 级变更**：放宽（block→review→auto）必须双人复核 + 24h 冷静期；收紧可走快速通道。原则：**宁可多批十张卡，不轻易松一条规。**

## 4.8 /p7 装配中心——Bundle 版本与灰度

行业包版本矩阵（哪个客户跑哪个版本）、灰度批次控制台、起飞前检查单。
**操作**：批次推进审批（R-PL5）、观察期数据查看、手动暂停、审批回滚（回滚也要审批——防误回滚）。

## 4.9 /p24 考试院——考试与红队

考题库（含每道题的golden answer 与判卷结果）、员工成绩单、红队对抗记录。
**你的用法**：①新员工（新 preset 版本）上岗前看成绩；②把本周 AI 答错的真实案例「一键转考题」——让每一次事故都死于下一次考试。

## 4.10 /p23 组织记忆——不复蹈覆辙的地方

策略墓地（失败策略+教训）、复盘档案、学习周刊。
**纪律**：批策略前先到墓地查重；复盘会结论必须落成记忆条目（系统自动提醒）。

## 4.11 /p25 开发场域——AI 开发监督

ai-pm V3 流水线产出的 PR 列表（每个 PR 已带：变更分级 C0-C3、G1-G5 闸门证据、影响范围分析、回滚方案）。
**评审清单**：①分级是否合理（就高不就低）②闸门证据全绿 ③影响面自评 vs 系统 blast-radius 分析是否一致 ④回滚方案是否具体（"revert 即可"不算方案）。

## 4.12 /p3 掌上日报 & /p6 技能中心

- /p3：移动端日报——通勤路上 5 分钟扫完昨天；
- /p6：技能目录与健康度（零调用技能会标黄——7 天零调用自动探针试跑）。

# 第五部分 剧本篇：七大业务域标准动作

## 5.1 工单与服务（你的角色：抽查者 + 兜底人）

- 常规：AI 全闭环，你不碰单；
- 需介入队列：AI 已带完整上下文摘要（客户画像/诉求/已做动作/建议方案），你**零信息差接管**——大多数情况下你只需确认 AI 建议的方案然后点发送；
- 投诉升级：客户情绪负面自动升优，你在 15min 内出现（手机端可处理）；
- 关单第 3 天自动回访，不满意重开——你每周看重开率（>8% 说明"已解决"的水分大）。

## 5.2 需求与研发衔接（你的角色：闸门 PM）

你只在一个点出现：**R-PL3 立项审批**。此前（澄清/确认单）和此后（开发/评测/发布/交付/回访）全自动。
- 批之前看热度：客户数 × 健康分 × ARR 权重——同样的需求，为 30 家健康客户做优先于为 1 家做；
- 驳回要给理由（"暂不做的原因"也是服务，系统会替你回传给客户）；
- 多家同求自动聚合为同一 requirement，交付时逐单通知——不用你管。

## 5.3 知识库（你的角色：总编）

- 待发布条目审批（R-PL8）：口径一致性是你唯一的核心判断；
- 每周二看：命中率（目标 ≥80%）、缺口 Top10、「被点未解决」榜；
- 答错一键纠错 → 系统自动完成：知识修正 + 考题增补 + 员工扣分。

## 5.4 客户成功（你的角色：审批关怀动作，不亲自写话术）

- 健康分三级分流：**健康**（零打扰，进周报）、**预警**（AI 生成关怀任务，你批量审批）、**高危**（值班人即时介入——这时你才亲自上）；
- 续费三级预警（60/30/7 天）：AI 会生成《客户价值报告》（使用深度/ROI/业务成果），你审批后由 CSM 通道送达；
- 频控红线：同一客户 7 天被动触达 >2 次系统自动阻断——客户被骚扰是慢性病，宁可少触达。

## 5.5 计费账务（你的角色：管钱的人，零错误预算）

- 对账每日自动（02:00）：零差异你不用看；**有差异 = 已自动冻结该租户资金流 + P1 找你**；
- 客户问"积分怎么扣的"：AI 30 秒自动答（哪个员工/什么任务/什么档位/扣多少）；
- 争议升级到你：带上对账投影与客户沟通——**先查账，再谈赔**；
- 退款审批见 4.2 清单。月度账单 1 号自动推送客户管理员。

## 5.6 行业包与灰度（你的角色：批次守门员）

- 每个批次启动前你审批（R-PL5）；观察期 24h 数据自动采集，**超阈值系统自动暂停**（不需要你在场）；
- 暂停后：故障应急官已拉起诊断，你看诊断结论决定「修复后恢复（resumeApproved）」还是「审批回滚」；
- 新版本上架：五项检查单（脱敏/考题/围栏绑定/schema 兼容/回滚可用）+ 你与上架审核官双审。

## 5.7 策略中心（你的角色：自生长引擎的刹车与油门）

- 策略九要素审查（缺度量指标一律打回）；
- 灰度是所有策略的默认出生方式——要求全量一步到位的必须写明理由；
- 熔断优先于审批：触发熔断条件的策略系统自动暂停，你事后看判令；
- 每周一效果榜过堂（见 3.2）。

# 第六部分 应急篇：故障来了怎么办

## 6.1 故障分级与你被找到的方式

| 级别 | 定义 | 找你的方式 | 你的时限 |
|---|---|---|---|
| P0 | 数据安全/账本断链/全平台不可用/需主备切换 | **电话+短信+App** 三通道 | 5min 内确认 |
| P1 | 核心功能受损/对账差异/保护文件被改/僵尸熔断/漏触发 | App+移动推送 | 15min 内响应 |
| P2 | 有降级的局部异常/灰度自动暂停/容量预警 | 清晨决策包 | 当日 |
| P3 | 趋势性风险 | 策略中心/周报 | 本周 |

## 6.2 应急六步（背下来）

**① 发现 → ② 宣告 → ③ 止血 → ④ 诊断 → ⑤ 恢复 → ⑥ 复盘。**

- **宣告**：在事件中确认级别与你的身份（值班人）。系统已开始计时；
- **止血优先于诊断**：先让损失停止扩大——可用的止血动作（全部一键化）：
  - `冻结变更`：全局冻结一切非 hotfix 变更；
  - `冻结资金`：冻结相关租户自动资金流；
  - `灰度暂停/回滚`：批次级止血；
  - `降级`：非核心路径读快照（核心路径永不降级）；
  - `主备切换`：满足三条件系统已自动切（见 6.3）；
- **诊断**：事件账本时间线 + 全链路 trace（从一张工单可跳到完整链路）；
- **恢复**：回滚（代码 revert / Bundle 快照 / 配置版本回退，全部一键）；
- **复盘**：48h 内，故障应急官已起草时间线，你主持根因五问，产出整改工单 + 知识条目 + **新考题/新围栏**。

## 6.3 主备切换（你需要知道的全部）

- **自动切换**（已授权）：探针连续 3 分钟全断 + 备库健康 + 抢到 fencing 租约 → 系统自动切，同时电话通知你（先斩后奏）。你接到电话后的动作：确认切换事件、宣告 P0、监督回切计划；
- **人工切换**：主系统未全断但全面崩溃（如全 500）→ 你与 Owner 双人确认（10 分钟裁决窗）；
- **禁止切换**：备库复制延迟 >60s 或验链失败时，系统拒绝切换并告警——此时转入本地抢修；
- **回切**：主库修复后先当 24h 备库 → 数据校验（验链+余额比对零差异）→ 5% 灰度回切 24h → 全量。回切也是一次灰度发布。

## 6.4 AI 失控专项预案（本系统特有）

| 场景 | 系统已自动做的 | 你要做的 |
|---|---|---|
| AI 开发产出带病代码 | G1-G5 闸门拦截；漏网则灰度观察期自动暂停 | 审批回滚；把漏网路径转成新测试用例 |
| AI 误删底层文件 | 保护清单闸 deny（删除围栏/迁移/sync 类文件系统级拒绝） | 若告警送达你：确认带外修改 P1，从镜像仓恢复 |
| AI 错误变更业务资产 | 围栏 R-PL 系列拦截高危项；围栏异动 3σ 检测 | 冻结该资产；查异动根因 |
| AI 连续低质量输出 | 员工成绩下滑 → 自动重考/技能回滚 | /p8 暂停该员工，任务转备份岗位 |
| 全面失控（极端） | 「经营总闸」：一键暂停全线自动化 | 你从 /p1 拉下总闸，系统退回全人工模式，然后慢慢查 |

# 第七部分 红线篇：你绝不能做的八件事

1. **绝不绕过审批直接改生产**——所有变更走闸门，hotfix 也只走快轨不走侧门；
2. **绝不导出客户原始经营数据**（R-PL4，系统级 block，你也没有权限）；
3. **绝不共享账号**——一切操作落账本到个人；
4. **绝不放宽围栏换清净**——审批量大应该优化证据链与聚合，不是松规则；
5. **绝不批没有度量指标的策略**；
6. **绝不在对账有差异时批准退款**；
7. **绝不带病切换备库**（系统也会拒绝）；
8. **绝不让复盘停在口头**——每次事故必须产出整改工单+知识条目+新考题，否则同类事故一定会再来。

# 附录 B 常见问题

**Q：审批太多批不完怎么办？**
先看结构：同类多 → 让策略工程师聚合/提高该类自动化置信度；证据链看不懂 → 提需求改审批卡（不要靠猜批）。审批量本身是该被系统消化的指标，不是你的体力竞赛。

**Q：我能相信 AI 的建议吗？**
能信「证据链」，不能信「结论」。每条建议都要能下钻到原始数据；抽验不合格即触发该类置信度降级——信任是动态校准的，不是一次性授予的。

**Q：客户要求人工服务怎么办？**
投诉/高危单本来就会到「需介入」队列。客户点名要人工 = 服务分级信号，该单转你，同时记为 AI 服务的失败样本回流改进。

**Q：什么情况下该考虑加人（1-2 人不够用）？**
系统会告诉你：①审批日均超 4h 且聚合优化后仍超；②P1 响应达标率连续两周 <90%；③自动化率连续两月不升反降。三条命中两条，提扩容评估（第九部分升级建议有对应机制设计）。

# 第九部分 差距评估与升级建议（手册之外的系统体检）

> 以「1–2 人服务千万级客户」为标尺，对当前仙女座做一次诚实的差距评估。以下按优先级排序，均已映射到可落地的工程动作。

## 9.1 已具备（可以放心依赖的）

- 数字员工全员编制、围栏红线、考试院、账本审计、自生长闭环（产品篇全部落地）；
- 工程底座：实时面/投影/熔断/灰度/热更新/容量模型（代码+101 测试全绿）；
- 安全保障：变更分级、保护清单、主备切换判据、镜像备份（已实测）。

## 9.2 差距清单（必须升级才能真正 1–2 人 @ 千万级）

| 优先级 | 差距 | 影响 | 升级方案 |
|---|---|---|---|
| **U1（最高）** | **审批信息压缩比**：当前审批卡证据链是"数据"，还不是"判断"。1-2 人的瓶颈在审批认知带宽（日均 200+ 卡时 3min/卡 不可持续） | 审批质量随量下降 | ①审批卡升级「AI 裁决建议书」：结论+三方证据摘要+反方意见+相似历史审批对照（点一次看完）；②同类聚合审批+抽验比例自适应（抽验不合格率驱动）；③「默认动作库」：你批过的同类决策 3 次一致 → 系统提议固化为规则（你批准一次，永久免批同类） |
| **U2** | **告警触达通道**：P0 电话/短信通道目前是设计态（代码里是三通道判据，实际只接了 App 推送） | 夜间 P0 可能叫不醒人 | 接入通道商（语音电话+短信 webhook），落实"5min 未确认升二线"的升级链；每月自动测一次通道（测试呼叫） |
| **U3** | **生产级适配器**：事件总线/缓存/租约当前为内存实现（起步形态） | 万级租户后内存实现不达 | 按既有接口换 NATS JetStream/Redis 适配器（接口已隔离，上层零改动）；ClickHouse 暂用 PG 物化视图 |
| **U4** | **移动端值班体验**：审批/宣告/止血动作需在手机端全功能可用（当前 PC 为主） | 单人值班时被困在电脑前 | 移动端三件套优先：审批卡、P0 宣告与止血五键、决策包 |
| **U5** | **自动化率度量看板**：1-2 人编制的核心仪表盘（自动化率/审批量/误判率/加人信号） | 无法判断"什么时候该加人" | /p21 增加「编制健康」看板：审批日均耗时、P1 响应达标率、自动化率趋势、加人三信号自动判定（附录 B 的三条） |
| **U6** | **演练自动化（drill-runner）**：故障注入演练目前是手册流程 | 季度演练靠自觉，恢复能力未实证 | 实现 drill-runner：一键注入（杀容器/停库/删文件沙箱副本）+ 自动计时 + 验收断言 + 演练报告自动生成进知识库 |
| **U7** | **知识命中率飞轮**：命中率 <80% 时的补救目前是"每周二人工看" | 客服自动化第一指标可能阴跌 | 命中率周环比 -5pp 自动生成策略提案（知识补全专项）；缺口聚类直接生成知识草案（人审即发） |
| **U8** | **客户侧入口打磨**：技术支持入口 FAQ 已有，但客户侧的「服务透明页」（我的工单/我的积分明细/服务状态公告）是体验关键 | 客户不信任=工单量虚增 | 客户侧三页：工单时间线（看得见的"在办"）、积分明细自助查询、平台服务状态页（故障时客户自查而非爆工单） |
| **U9** | **大规模时的分片运营**：千万级客户下，单一审批队列会拥塞 | 超大规模后的组织瓶颈 | 租户按行业/规模分片，审批队列按片路由；编制从"1-2 人管全部"演进为"1-2 人管 N 个分片的系统"（加的是分片自动化，不是人） |

## 9.3 不建议做的（避免过度设计）

- **不建议**现在上 Kafka/Flink/多活——按伸缩阶梯，万级租户内当前架构足够（4 倍余量），超 5 万租户再评估；
- **不建议**为"看起来更 AI"加闲聊型功能——运营系统的每一分自动化都要能审计；
- **不建议**放宽频控/退款等红线换短期客户满意度——墓地里的策略尸体都死于这个。
