# WorkLoom 三端同源改版阶段发布记录（2026-09-16）

## 发布口径

本次按算力预算收口为 **本阶段正式稳定发布** `ui-v0.1.1`。完成优于完美：本版本正式承接已经通过门禁的基座能力；不阻断本阶段的审计问题继续登记到后续迭代。九仓升级状态仍按真实结果记录，不因版本正式发布而误报。

已完成并进入基座候选版：

- 三端共享 UI、左侧统一导航、内容溢出保护、客户端中文文案边界与布局治理；
- 基座同步范围 v10、公共增量迁移、新行业完整迁移基线和依赖闭包收口；
- 围栏、租户能力与落地向导面向客户端的原始英文代码字段脱敏；
- 产品清单驱动的仓库、产品名、演示工作区、演示成员和端口派生能力；
- PC、B 端移动、C 端移动浏览器标题由同一产品清单注入；
- PC/B 移动/C 移动关键身份会话键按产品与客户端隔离；
- 公共发行脚本不再固定发布到 `workloom-im` 仓库。

本候选版已执行的最小发布门禁：

- 全仓 TypeScript 类型检查；
- PC B 端、移动 B 端、移动 C 端生产构建；
- 产品身份解析测试、同步引擎测试、脚本语法检查；
- Git 差异检查与暂存区秘密扫描。

## 已确认但延后处理的问题

以下项目不能在后续正式版中遗漏：

1. 八个下游仓只能接入新的不可变三端稳定快照 `ui-v0.1.1`；`ui-v0.1.0` 含基座产品名和 `ai-pm-demo` 默认值，不得再作为下游最终版本。
2. 清除受管客户端中剩余的可见基座品牌硬编码，包括环境守门页、欢迎仪式、注册页、侧栏、B 移动登录页和 PWA 清单；统一从 `product.manifest.json` 派生。
3. 给 B 移动 Service Worker 缓存加产品命名空间，并限制清理范围，禁止同源多产品互删缓存。
4. 完成 PC 布局、影音、数字人浮层、导航偏好等全部本地存储键的产品级隔离；保留可审计的旧键迁移策略。
5. 完成 Electron/Windows 桌面载荷的产品清单随包、数据库/NATS/服务端口派生、支持目录隔离、动态诊断标题与动态进程名。
6. 清理 `docker-compose` 与本地启动、停止、预览、体检脚本中的固定容器名和固定端口。
7. 为稳定客户端快照新增行业中立扫描和双虚拟产品 materialize 测试，阻断产品名、工作区、成员、缓存和存储命名空间串包。
8. 为八个下游仓补齐 `demoWorkspaceSlug`、`demoMemberNo` 等受保护身份字段，只允许 Bundle、主题变量、投影、配置与权限表达行业差异。
9. 依次完成八个下游仓的最终基座同步、`ui-v0.1.1` 三端接入、依赖锁定、全量测试、PR、合并和主分支验真。
10. macOS/Windows 签名安装包仍需要对应平台签名证书；GitHub 令牌只能完成源码、标签、Release 和制品上传，不能替代签名证书。

## 恢复顺序

额度恢复后从本记录继续，顺序固定为：

1. 在 `workloom-im` 完成上述治理盲区并跑完整门禁；
2. 以 `ui-v0.1.1` 为起点发布下一版稳定标签与校验制品；
3. 按 Andromeda、Eagle、Hotel、HyperReality、获客、Panda、Tiger、Fox 的波次完成升级；
4. 每仓必须在自己的产品清单身份下通过三端构建、测试、秘密扫描和主分支验真；
5. 九仓全部完成后，才可宣告“正式稳定发布与全仓同步完成”。
