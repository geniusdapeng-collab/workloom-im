## 尚缺的真实验收材料

1. 完整行业装配夹具：隔离 PostgreSQL 已验证迁移、RLS 和单 active 数据库约束；仍需在修复并稳定基座种子夹具后做“旧装配运行 → 候选考试 → 切换中故障回滚 → 快照恢复”的发布级故障注入，不以本轮纯函数验证冒充该项结果。
2. H5：需要真实公网域名或工作区 URL 映射、反向代理、工作区路由绑定，以及正式身份提供方。当前若仅启用演示身份，会如实显示“仅预览”。
3. 微信小程序：需要 AppID/Secret、合法域名、正式登录换取验证及订阅消息真实发送器；仅填写凭据仍显示“部分接入”。
4. 支付宝小程序：需要 AppID/密钥、签名换登实现和服务通知发送器；仅填写凭据仍显示“部分接入”。
5. 发布与同步：本轮按边界未执行 Git 提交/推送、行业仓 base-sync 或线上发布验收。

## 生产环境验收顺序

1. 应用 0029 迁移，并在应用角色下验证 RLS 仅可读取当前工作区。
2. 用同一账号的两台设备分别暂停、刷新、续办；再用不同角色验证进度隔离。
3. 两名成员同时保存同一草稿，确认旧版本写入被拒；由所有者交接责任人后再继续。
4. 保持旧行业运行，生成并预览候选装配；在考试失败时确认旧装配不变；通过后确认只有一次原子切换事件和一份可用快照。
5. 对切换后装配执行回滚，核对旧资产精确状态恢复，并确认回滚前的新装配也有反向快照。
6. 配置真实 C 端 URL 与工作区路由，分别从非内网手机扫码、复制链接访问；逐渠道以真实回执验收，不以“凭据已填”代替发布成功。
